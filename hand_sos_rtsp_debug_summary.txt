==================================================================
สรุปปัญหา: Hand SOS Detection บน RTSP — False Positive สูงผิดปกติ
==================================================================
วันที่วิเคราะห์: จาก debug_rtsp_live.csv, debug_rtsp_hand2.csv, debug_rtsp_hand3.csv
(ทั้ง 3 ไฟล์เป็นภาพจริงจากกล้อง RTSP ที่ไม่มีใครทำท่า SOS จริง — hard negative)

------------------------------------------------------------------
1. อาการที่พบ (จากข้อมูล)
------------------------------------------------------------------
- debug_rtsp_live.csv  (60 วินาที) : state=3 (SOS เต็มรูป) เกิด 51 ครั้ง
- debug_rtsp_hand3.csv (11 วินาที) : state=3 เกิด 13 ครั้ง (เฉลี่ยทุก <1 วินาที!)
- debug_rtsp_hand2.csv (13 วินาที) : state=3 เกิด 1 ครั้ง (มือแทบไม่ถูกตรวจเจอเลย)

- ใน 3 ไฟล์รวมกัน: state=3 เกิดจาก "allow_fast_sos" (การกระโดด state 1 -> 3
  ข้าม state 2) คิดเป็น 63/65 ครั้ง (~97%)
- state=2 (thumb_in ถูกยืนยันแล้ว) แทบไม่เคยถูกบันทึกเลย (1 แถวจาก 1,158 แถว)
  แปลว่า state machine 3 ขั้นที่ออกแบบไว้ (palm_open -> thumb_in ->
  fingers_closed) แทบไม่ได้ถูกใช้งานจริง ทุกอย่างวิ่งผ่าน fast_sos shortcut
- พบการ "กระพริบ" สลับ state 1<->3 ต่อเนื่องในบาง track (เช่น tid=23:
  1,1,3,1,1,3,1,3,0,1,1,3,1,3) ไม่ใช่การค้าง state 3 แบบท่า SOS จริง
- พบ 1 กรณีที่ trigger state=3 ตอน hand_span=0.0033 (มือเล็กผิดปกติ/
  น่าจะเป็น noise ไม่ใช่มือจริง) แสดงว่าไม่มีการกรองขนาดมือขั้นต่ำ
  ก่อนอนุญาตให้เข้า fast_sos
- ในบรรดา 50 ครั้งที่ jump ผ่าน live.csv มี 25 ครั้ง (50%) ที่ palm_open=True
  พร้อมกับ fingers_closed=True ในเฟรมเดียวกัน ซึ่งขัดแย้งกันเองทางตรรกะ —
  บ่งชี้ว่า geometry check (โดยเฉพาะ Tier 2/3 ใน _fingers_closed) ไม่เสถียร
  เมื่อ keypoint กระตุกจากระยะไกล/ความละเอียดต่ำของ RTSP

------------------------------------------------------------------
2. สาเหตุหลัก (Root Cause)
------------------------------------------------------------------
A) allow_fast_sos (ใน check_sos_step, state 1 -> 3) เงื่อนไขหลวมเกินไป:
   เช็คแค่ "นิ้ว 3/4 โค้งงอ (tier-1 distance ratio 1.40) + มือไม่กางเต็มที่"
   ซึ่งเป็นท่ามือธรรมชาติทั่วไป (พักมือ, จับของ, ขยับระหว่างเดิน) ไม่ใช่
   ลายเซ็นเฉพาะของท่า SOS

B) ไม่มี temporal persistence ก่อนยิง alert:
   state=3 แค่เฟรมเดียวก็ถือว่า trigger ทันที ทั้งที่ thresholds.yaml
   มี hand_sos.temporal_window=10, temporal_threshold=0.4 อยู่แล้ว
   แต่ check_sos_step() ไม่ได้ใช้ค่านี้เลย

C) ไม่มี minimum hand-size gate ในเส้นทาง fast_sos:
   มือขนาดเล็กผิดปกติ (hand_span ต่ำมาก, อาจเป็น noise) ก็ผ่านเข้า
   fast_sos ได้เหมือนมือจริง

D) Tier 2 (y-based) และ Tier 3 (curl-based) ใน _fingers_closed()
   ถูกออกแบบมาช่วยกรณี keypoint คลาดเคลื่อน แต่กลับเป็นตัวการที่ทำให้
   fingers_closed และ palm_open เป็น True พร้อมกันได้ในภาพ RTSP ที่
   keypoint ไม่เสถียร ทำให้ state กระพริบ 1<->3 ถี่

------------------------------------------------------------------
3. คำแนะนำการแก้ไข (เรียงตามผลกระทบ/ความสำคัญ)
------------------------------------------------------------------
[ลำดับ 1 - ทำก่อน] เพิ่ม temporal persistence ก่อนยิง alert จริง
  - ห่อ state=3 ด้วย CooldownEngine (มีอยู่แล้วใน pipeline.py) หรือ
    บังคับให้ state ค้างที่ 3 ต่อเนื่อง >= 3 เฟรม (~0.3-0.5s ที่ 10fps)
    ก่อนถือว่าเป็น SOS จริง แทนที่จะ trigger จากเฟรมเดียว

[ลำดับ 2 - ทำก่อน] เพิ่ม minimum hand-size gate ก่อนเข้า fast_sos
  ตัวอย่าง:
    MIN_HAND_SPAN_FOR_FAST_SOS = 0.04  # ปรับตามข้อมูลจริง (median ตอน trigger = 0.055)
    if self._allow_fast_sos:
        if hand_span >= MIN_HAND_SPAN_FOR_FAST_SOS and \
           self._fingers_closed_strict(lm) and not self._palm_open(lm):
            return 3

[ลำดับ 3] เข้มงวด fast_sos threshold เพิ่มเติม
  - เปลี่ยนเกณฑ์ผ่านจาก 3/4 นิ้ว เป็น 4/4 นิ้ว ใน _fingers_closed_strict
  - ลด fingers_closed_ratio จาก 1.40 -> ประมาณ 1.15-1.25

[ลำดับ 4] ปิด/ลดการใช้ Tier 2 กับ Tier 3 ใน _fingers_closed()
  โดยเฉพาะสำหรับเส้นทาง fast_sos ให้ใช้ Tier-1 (distance-based) อย่างเดียว
  เพื่อลดโอกาสที่ fingers_closed กับ palm_open จะ True พร้อมกัน

[ลำดับ 5] ตรวจสอบว่า min_hand_bbox_area_norm (0.0015 ใน thresholds.yaml)
  ถูก apply จริงก่อนเรียก check_sos_step() ในทุกจุดที่เรียกใช้ detector
  (ไม่ใช่แค่ที่ main.py) — ใส่ log ยืนยัน เพราะพบ hand_span เล็กผิดปกติ
  หลุดผ่านมาได้ในข้อมูล debug

------------------------------------------------------------------
4. ขั้นตอนถัดไปที่แนะนำ
------------------------------------------------------------------
1. แก้ไขตามลำดับ 1-2 ก่อน (ผลกระทบสูงสุด ความเสี่ยงต่ำสุด)
2. รัน debug ซ้ำกับ debug_rtsp_hand3.csv (ไฟล์ที่ false-trigger ถี่สุด)
   ดูว่าจำนวนครั้งที่ state=3 ลดลงแค่ไหน
3. ถ้ายังไม่พอ ค่อยปรับเพิ่มตามลำดับ 3-4
4. เก็บ debug CSV ชุดใหม่หลังแก้ไข เพื่อเทียบผลก่อน/หลัง
